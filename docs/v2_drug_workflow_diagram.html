Drug utility path — how the modules interact

Deterministic code owns the control flow; the LLM fills two kinds of slot — a doer and a reviewer — on a bounded refine loop, and the trustworthy facts (rxcui, ATC, POTTR class) are deterministic lookups, never LLM guesses. Each distinct drug is resolved and researched once and reused across every trial. Output = six 3NF relational tables.

Guiding principle — research once per drug, reuse everywhere

A drug's intrinsic facts depend only on the drug, not the trial or the raw string — so they live once, keyed by a namespaced canonical_id, and every trial that uses the drug is a pure lookup. The expensive LLM + web search runs once per distinct drug (~2,400 raw tokens → ~1,300 canonicals); an existing, non-stale drug is never re-researched. Normalization is the speed win.

Guiding principle — the reviewer only advises; deterministic facts aren't LLM'd

Each judgement stage pairs a doer (web search) with an adversarial reviewer that returns only a verdict + problems, never a rewritten value; on a failure the critique feeds back to the doer (bounded, ≤3 attempts). The reviewer judges plausibility from its own knowledge — it does not re-search. The identity/classification facts that must be exact — rxcui + ATC (RxNorm), POTTR drug class, trial provenance — bypass the LLM entirely.

doer → reviewer

  • brand / code → INN (Keytruda, MK-3475 → pembrolizumab)

Stage 2 · enrichment

Annotate — the drug's intrinsic facts + mechanism

doer → reviewer
doer · web search
  • modality — exactly one of a controlled 12-term vocabulary
  • (target, action) pairs — one per target (an ADC lists antigen + payload)
  • drug_class, coarse FDA / EMA status, per-fact sources
reviewer
  • modality valid & correct; targets correct and complete
  • class sensible; FDA/EMA coarse + correctly formatted; sources present

Approvals — TGA / PBS, per indication

doer → reviewer
doer · web search (official sources)
  • one entry per distinct oncology indication, as the regulator states it (cancer + biomarker + line + combination …)
  • per-agency TGA and PBS status / date / evidence link, set independently
  • investigational drug → empty list (no invented approvals)
reviewer
  • right specificity — biomarker / combination qualifiers not dropped

Phase 2 · role

Classify — main vs auxiliary, per arm

doer → reviewer · no web

Runs once per trial arm (not per drug), after identity/enrichment so each drug's canonical id + class are known. A cheap judgement from the arm context alone — no web search.

doer
  • each drug → main (the investigational / defining agent under study) or auxiliary (backbone / SoC / comparator / placebo / premedication)
  • signals: arm_type (a control arm is typically all-auxiliary), a novel agent (name: id, no RxNorm entry)
  • echoes each canonical_id exactly — one role per drug
reviewer + deterministic guard
  • investigational=main; backbone/SoC/comparator/placebo=auxiliary; a control arm not spuriously main
  • guard: every drug labelled once · role ∈ {main, auxiliary}
→ trial_arm_drug_rolejoins to drug_regulatory_approvals on canonical_id → per-main TGA/PBS

The relational model — three stages, six tables

Identity (which drug is this?) is separated from enrichment (what is this drug?) and from role (what part does it play in this arm?). Trial provenance joins to the mapping by input name and to the shared trial_arms registry (arm identity, both registries) by trial_arm_id; everything downstream joins by canonical_id. (trial_arms is shared with the eligibility path — not one of the drug path's six.)

Stage 1 · identity

intervention_to_canonical

input_intervention_name → canonical_id

the mapping (+ raw_name_to_map); a combination is 1 input → N rows.

Stage 1 · provenance

trial_to_intervention

trial_arm_id → input name

which trial arm used each name; links to the shared trial_arms registry (arm identity lives there once). Deterministic.

Stage 2 · core

canonical_id (PK)

modality, class, rxcui, atc, POTTR class, FDA/EMA, aliases, researched_on.

Stage 2 · mechanism

drug_target_actions

(canonical_id, target, action)

the mechanism as (target, action) pairs — the queryable dimension.

Stage 2 · regulatory

drug_regulatory_approvals

(canonical_id, indication)

TGA / PBS approval per as-stated indication + evidence links.

Phase 2 · role

trial_arm_drug_role

(trial_arm_id, canonical_id) → role

main / auxiliary per drug per arm; joins to drug_regulatory_approvals for per-main TGA/PBS.

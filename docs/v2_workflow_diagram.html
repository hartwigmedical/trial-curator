Extract → check → refinethe heart of the workflow · same extractor & panel for both registries

One agent generates the candidate table; a panel verifies it. Verification is an easier task than generation and runs on a fresh pass with the finished table in view — so it catches omissions the generator missed. Failures are fed back and the extractor redoes the work, up to 3 attempts.

① Extract · 1 LLM agent

Reads the assembled document + cohort list → the candidate DNF table.

Essential tasks
  • emit whole rows — one ANDed conjunction each; OR-alternatives → separate rows
  • fill the 5 columns; leave "" when a criterion isn't required
  • wrap exclusions in NOT(); keep same-column carve-outs in one cell
  • tag every value with its source section [a; b]
  • assign each row a cohort scope: C1… or trial-wide

② Check · rule-check (code), then 5 reviewers (parallel)

Each reviewer sees the whole candidate table + source and judges ONE dimension → faithful? + problems.

Essential task per reviewer
  • cancer_typeis it the tumour under study? reject a tumour seen only in a prior-therapy / history / exclusion line — e.g. drop "melanoma" from a lung trial. gates
  • molecularfaithful + right column: HER2 IHC → biomarker, ERBB2 amp → gene, MSI-H → signature. gates
  • prior_therapyrequired / excluded only; omit merely-permitted; exclusions must be NOT(). gates
  • structuralconjunctions & OR-rows correct; each row's cohort scope right. gates
  • drugeach cohort's drug matches its arm's intervention. advisory
✓ passrules pass and all four gating reviewers are faithful → leave the loop.
↺ redoany gating reviewer fails → its problems are appended to the prompt; the extractor re-extracts, then re-checks.
■ stopafter 3 attempts, exit as faithful=False — best effort, written & logged for the curator.

Stage II — mappingruns on the extracted DNF table · every procedure is an LLM mapper → reviewer (same refine loop)

Each normalized cell is mapped to a controlled representation, then reviewed. The legacy curation resources ground the prompts, few-shot examples, and tests — so deviations from the previous workflow stay marginal.

Eligibility path — how the modules interact

Deterministic code owns the control flow; the LLM fills two kinds of slot — a doer and a reviewer — on a bounded refine loop. Everything runs once per trial, writing the arm spine to the shared trial_arms registry (keyed by trial_arm_id) and the eligibility content to normalized 3NF masters (the combined flat view is materialized separately — see Write).

Guiding principle — one agent per independent task

Split work into a separate agent only when the sub-tasks are genuinely independent. Outputs that must be decided together stay in one agent (a DNF — disjunctive normal form — row is a conjunction across columns → one extractor emits whole rows). Independent checks fan out (→ a panel of focused reviewers). Deterministic work gets zero agents.

Guiding principle — the reviewer only advises; the doer is the sole writer

Every check — the deterministic validators and the LLM reviewer — returns only a verdict + problems, never a rewritten value (ReviewVerdict has no output field). On a failure the critique is fed back to the doer, which re-generates (evaluator–optimizer / Reflexion — not an editor). One writer ⇒ no unchecked edit can reach the output, and every accepted value was re-checked after it was written. Trade-off: it pays full re-generation and can stall convergence on the hardest trials.

Stage I — extractionextract → check → refine · the bounded evaluator–optimizer loop at its heart (the shared core/review.py harness — the same loop Stage II uses)

One agent generates the candidate table; a panel of agents verifies it. Verification is an easier task than generation and runs on a fresh pass with the finished table in view — so it catches omissions the generator missed. On a gating failure the loop does incremental repair: the extractor gets its OWN previous table + only the flagged issues and keeps unflagged rows verbatim (preserves correct work, aids convergence), up to 6 attempts.

doer · extract

Reads the assembled document + cohort list → the candidate DNF table (whole rows, so cross-column co-occurrence is preserved).

Essential tasks
  • one row = one ANDed conjunction; OR-alternatives → separate rows
  • fill 5 columns (cancer_type, gene_alteration, molecular_signature, molecular_biomarker, prior_therapy); "" when not required
  • exclusions inline as NOT(...); same-column carve-outs stay in one cell
  • never write a self-contradiction X AND NOT(X) in one cell — if the same thing is required for one cohort and excluded for another, split into rows
  • cancer_type: CONDITIONS is authoritative; never AND two different tumour types; drop a broad umbrella when the trial is clearly one specific type
  • capture tumour-type exclusions (“except / excluding / other than”) as a same-cell NOT(...) — never drop a stated carve-out
  • judgement, no over-enumeration: don't emit near-duplicate OR rows that differ only by a subsuming clause (e.g. one adds AND refractory to standard therapy) — keep the single version applying to most patients
  • tag every value with its source section(s) [a; b]
  • assign scope from the FIXED cohort list: each criterion to exactly one scope — a cohort id, or trial-wide only if shared by ALL cohorts; never restate a criterion (esp. a single-valued axis like cancer_type) across scopes
Examples
[trial-wide] cancer_type = "ES-SCLC AND NOT(complex SCLC) [TITLE; ELIGIBILITY CRITERIA]" [C1] molecular_biomarker = "HR+ AND HER2- [ELIGIBILITY CRITERIA]" [trial-wide] prior_therapy = "NOT(prior anti-PD-1) [EXCLUSION CRITERIA]"

code checkdeterministic rule-check — at least one row, and no row with all five eligibility columns empty; a failure goes straight back to the doer (no reviewer call).
reviewer · 5-agent panel (parallel)

Each reviewer sees the whole candidate table + source and judges ONE dimension → faithful? + problems. Independent checks → separate agents (the guiding principle).

One reviewer per dimension
  • cancer_typetumour under study? reject one seen only in a prior-therapy / history / exclusion line (e.g. drop "melanoma" from a lung trial); flag ANDing two different types, an un-dropped umbrella, or a dropped tumour-type exclusion. gates
  • molecularfaithful + right column (HER2 IHC → biomarker, ERBB2 amp → gene, MSI-H → signature); flag a cell's X AND NOT(X) (conflated cohorts → split rows). gates
  • prior_therapyrequired / excluded only (omit merely-permitted); exclusions wrapped in NOT(); flag over-enumeration (near-duplicate rows differing only by a subsuming clause). gates
  • structuralDNF integrity: conjunctions / OR-rows correct; each row's cohort scope right; a criterion in exactly one scope (no cross-scope duplication); no X AND NOT(X) or redundant subsuming rows. gates
  • drugeach cohort's drug reflects its arm's intervention. advisory (non-gating)

Stage II — mappingon the extracted rows · each procedure = doer → code check → reviewer, on the SAME shared refine loop as Stage I

Each normalized cell is mapped to a controlled representation, then reviewed — running on the same bounded refine loop as extraction (the shared core/review.py harness: on a gating fail the mapper re-generates from the critique, bounded attempts). Curated resources ground the prompts + tests but are held out as verification data (not ingested) — so it stays a mapping, not a vlookup. All three mappers are built & live-validated (cancer_type signed off; gene_alteration & molecular_signature validated on disjoint samples).

cancer_type → OncoTree

doerexpression → OncoTree name + code (e.g. "metastatic NSCLC" → NSCLC). Only 3 non-OncoTree terms allowed: Pan-cancer / solid tumour / Haematological malignancy (no [None]).

code checkreject invalid codes and logic errors: X AND X, X AND NOT(X), a broad term ANDed with its subtype, a subtype ANDed with its parent (hierarchy via is_subcode).

reviewerright node + granularity; structure preserved; NOT(cancer type) kept minimal.

grounds: OncoTree ontology as a single-source nested YAML resource — an indented Name (CODE) hierarchy that aids granularity (mapping/cancer_type/vocab.py) + a few held-out ConditionsCurationResource examples

gene_alteration / molecular_signature → finding-model

doer→ finding-model syntax: SmallVariant[gene=BRAF & …=p.V600E], Fusion[geneEnd=ALK], MicrosatelliteStability[…=MSI].

code checkfull finding-model grammar validation — fields / enums / scope + HGVS shape per class (CLASS_SPEC), not just brackets; no duplicate terms, no X & NOT(X). The hard syntax gate, so the reviewer judges only semantics.

reviewerfaithful + valid grammar (strict); a NOT() qualified by something inexpressible (e.g. a location) is omitted, not negated.

grounds: finding-model grammar (mapping/finding_model.py) + GeneAlteration/MolecularSignature examples

drug → main/aux + class + TGA/PBS

doer (web)main = the investigational agent(s) by judgement (not the whole regimen; backbone/SoC/comparator/placebo → auxiliary); POTTR + general class; per main drug TGA & PBS status (Approved/Not approved) + a detail column (year + evidence + official link), via web search.

reviewermain = investigational only; class sensible; per-drug status + detail present.

grounds: POTTR dataset + live web research (Responses API web_search)

three stagesevery column runs the SAME three, and each is a function of a single value — so a mapping cannot be perturbed by other values entering the corpus, and churn is structurally impossible rather than merely mitigated. 1 · translate (LLM doer→reviewer, above) → 2 · canonicalise (deterministic only — De Morgan, absorption, dedup, term/field ordering; a spelling normaliser that never changes meaning) → 3 · finalise (approved rulings from qa/adjudications/<column>.py, applied LAST).
no cross-value LLMstage 2 used to hand groups of “equivalent” values to an LLM to unify. That pass silently re-rolled 7 unrelated values in one run, undoing two reviewed improvements — so it was deleted from all three columns. Divergence is still detected and reported as residue; what is gone is the automatic re-decision. Anything it surfaces is fixed in stage 1’s prompt, or ruled on in stage 3.
outputs mirror itthree tables per column — <column>_map_{initial,reconciled,finalised}.tsv — with columns that accrete, so one row shows the whole chain and a difference between _reconciled and _finalised is an approved override, visibly. All nine come from one spec (mapping/stage_tables.py).
